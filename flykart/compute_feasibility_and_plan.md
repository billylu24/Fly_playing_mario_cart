# FlyKart 计算 / 显存可行性实测与后续试验计划

> 后续更新：已完成 CSR、自定义已有边梯度与 Triton 验证，全脑数量级合成图（165,122 节点 / 21,135,616 边 / B4 / T32）已通过全边权更新，张量峰值约 1.30 GiB。详情见 [sparse_operator_results.md](sparse_operator_results.md)。下文保留初次原生 COO 测试结果，其 OOM 结论只针对该实现。

日期：2026-09-12。结论：**当前 RTX 5070 可以开展小规模连接组循环网络实验；建议先用约 8 千神经元、百万级边、batch=4、展开 32 步，比较冻结连接与训练神经元增益。当前 PyTorch 原生 COO 全边权反向传播有 N² 中间计算，不能直接扩到约 16.5 万神经元。**

本次仅运行合成计算与显存探针：没有读取或转换真实 MaleCNS 连接表、没有修改原始数据，没有运行 PPO、游戏采样或策略训练。合成网络做少量反向传播和 Adam 更新，是为了实际分配梯度与优化器状态，不构成学会任务的证据。以下试验计划尚未执行。

## 1. 环境与测试口径

- GPU：RTX 5070，计算能力 12.0；NVIDIA driver 595.84。nvidia-smi 显示 12,227 MiB，PyTorch CUDA API 报告可分配设备总量 11,771.25 MiB；按各自 API 口径记录，不将两者混用。
- benchmark 开始时 CUDA API 空闲 8,607.31 MiB，机器上有桌面和其他 GPU 进程；未终止它们。结果不是独占 GPU 的精确性能排名。
- 独立环境 `.venv-bench`：Python 3.12.14、PyTorch 2.11.0+cu128、CUDA runtime 12.8、NumPy 2.5.3，依赖检查通过。环境约 6.5 GiB；原 `.venv` 仍是模拟器与数据检查环境。
- 浮点精度 FP32；PyTorch 原生 `torch.sparse.mm`、COO 布局；没有 AMP、编译、activation checkpoint 或自定义梯度内核。
- 每个配置独立子进程；一次 warmup + 三次计时，表中为三次测量中位数。每次包含 forward、backward、梯度有限性检查、Adam 更新；计时点执行 CUDA synchronize。
- 单进程 PyTorch allocator 上限设为设备总量的 55%，约 **6.32 GiB**，每例超时 120 秒。此限制为其他程序和 GPU 非张量开销留余量；OOM 表示在这个测试预算下失败，并非已穷尽整张显卡。
- 表中显存是 `max_memory_allocated` 的 MiB；不包含其他进程、CUDA context/库等非 allocator 内存，也不是整卡 nvidia-smi 用量。缓存保留峰值 `max_memory_reserved` 另存 JSON。计时/峰值窗口从图初始化后开始，不覆盖原始文件加载与图构建峰值。

### 合成模型

每个目标节点接收 128 条唯一边，E=N×128，采用规则循环连接和随机缩放权重，不是实际 MaleCNS 的度分布或生物通路。相同规模/批次/展开长度的三种训练方式使用相同随机种子和拓扑。

64 维随机输入 → Linear(64,128) encoder → 128 个输入节点 → 稀疏循环网络 → 128 个输出节点 → Linear(128,8) readout。

更新为 `h_next = 0.5*h + 0.5*tanh(gain*(W@h) + input)`。每个展开步执行一次网络更新，每步读出都贡献平方损失；T 表示连续可微更新步数，B 表示并行序列数。没有 CNN、真实视频、动作分布、价值学习或游戏 reward。8 维读出仅模拟小输出头。

比较方式：

| 名称 | 更新参数 | 梯度如何流动 |
|---|---|---|
| frozen | encoder、readout | 经过整个循环网络回到 encoder，W 固定 |
| gain | encoder、readout、每神经元一个 gain | W 固定，gain 可学习 |
| full | encoder、readout、所有现存边的权值 | 连接结构固定，边值可学习，gain 固定 |
| detach | 实际只有 readout 得到梯度 | 大脑与 encoder 在 no_grad 下运行，作为切断梯度对照 |

frozen 的 encoder/readout 共 9,352 个参数；gain 多 N 个参数；full 多 E 个参数。detach 的 JSON `trainable_parameters` 计入了配置在 optimizer 里的 encoder，但实际 encoder 无梯度，实际更新的只有 readout 的 1,032 个参数。

## 2. 实测结果

单元格格式为 **峰值张量显存 MiB / 每次合成更新 ms**。19 个配置中 17 个通过、2 个受控 OOM，没有超时。

| N | E | B | T | frozen | gain | full |
|---:|---:|---:|---:|---:|---:|---:|
| 2,048 | 262,144 | 1 | 8 | 38.5 / 6.4 | 38.6 / 5.4 | 160.9 / 7.4 |
| 8,192 | 1,048,576 | 1 | 8 | 101.8 / 9.9 | 102.1 / 10.0 | 591.3 / 25.4 |
| 8,192 | 1,048,576 | 1 | 32 | 102.6 / 38.0 | 103.7 / 38.5 | 2,229.5 / 123.1 |
| 8,192 | 1,048,576 | 4 | 32 | 106.2 / 39.6 | 110.2 / 39.6 | 2,229.7 / 128.5 |
| 32,768 | 4,194,304 | 1 | 8 | 355.1 / 58.2 | 356.4 / 58.2 | OOM |
| 32,768 | 4,194,304 | 1 | 32 | 358.2 / 251.1 | 362.4 / 244.4 | OOM |

detach 对照（N=8,192、E=1,048,576、B=4、T=32）：42.1 MiB / 8.5 ms。它不是可等价替代 frozen 的训练方案，因为 encoder 没有收到梯度。

对照梯度检查：

- frozen：encoder 和 readout 梯度存在且非零，边权无梯度。B=4、T=32 时 encoder 梯度范数约 9.78e-4。
- gain：上述梯度加 gain 梯度；同配置 gain 梯度范数约 1.22e-4。
- full：encoder/readout/边值都有有限梯度；同配置边值梯度范数约 6.02e-3。
- detach：encoder 梯度为 None，只有 readout 梯度。

这验证“冻结参数”和“切断梯度”是不同操作，但不证明长时间信用分配或真实视觉路径足够有效。

### 全边权反向传播为什么昂贵？

N=32,768 的 full 配置在申请 **4.00 GiB** 中间张量时失败。额外用 N=4,096、B=1 的单步 profiler 检查，反向传播出现：

```text
aten::mm: [4096,1] × [1,4096]
aten::mm: [4096,4096] × [4096,1]
```

第一项是边权梯度相关的 N×N 外积计算；profiler 该事件记录约 75.6 MB 设备分配（事件中还包含相关临时开销，不能全部认定为单个稠密张量）。对应一个 FP32 稠密 N×N 张量本身的理论大小：

| N | 一个 N×N FP32 张量 |
|---:|---:|
| 4,096 | 64 MiB |
| 8,192 | 256 MiB |
| 32,768 | 4 GiB |
| 165,122 | 约 101.6 GiB |

因此当前 `COO + sparse.mm + 原生边值 backward` 路径不适合直接全脑全边训练。不能把这个结论推广成“所有稀疏网络实现都不能训练全脑”；其他布局或只对现存边计算梯度的算子必须另外测量正确性和显存。

另外，N=8,192 的 full 从 T=8 到 T=32，显存从 591 MiB 增至 2,229 MiB，说明实际计算图/稀疏梯度中间存储也受展开长度影响。冻结连接避免了边值梯度路径，但跨时间 backward 仍有开销；32,768 节点时 backward 约占 237–244 ms，远超过 forward 的约 6 ms。

### 对真实 MaleCNS 的推断边界

本次没有测试真实全图或已筛选生物子图。16.5 万条 Traced 记录与“两端有注释”的 2,603 万条边不是同一个已确定网络，不能直接拼接成已测配置。

只按存储算术：E=26,028,386 时，COO int64 双索引 + FP32 权值约 496 MiB；再加一份边值梯度和两份 Adam 状态的理想静态总计约 794 MiB。这**不包括**图副本、稀疏梯度索引、时间展开、encoder、rollout、临时矩阵和 CUDA 库，所以不是训练显存预测。原生 N² 中间矩阵足以使“权重能放下”的估计失效。

规则图比真实不均匀连接更容易获得好的访存行为；真实数据性能可能更差。未测试混合精度，不能预先假定全部显存减半。计时不含模拟器与图像 encoder，不能换算成 RL 每秒游戏帧数或学会驾驶的时间。

## 3. 建议的后续试验计划（待执行）

### A. 数据选择与任务信号

先确定神经元纳入规则、检查视觉输入群到运动输出群的连通性；输出节点和边数、类型覆盖、递质缺失比例。选择有功能依据的约 2k–8k 神经元子图；不得为凑整数从真实神经元随机截取后宣称是完整视觉—运动系统。

独立核对游戏完赛、checkpoint 回绕、逆行及重置行为，分开成功/失败/超时。现有 Time Trial reset/按键已通过，但五圈完赛触发尚未实测；上游撞墙 done 不能视为成功。

交付：一份明确的子图选择规则和游戏状态判定表。此阶段不需要 PPO。

### B. 真实子图与真实 encoder 的资源验收

首先采用 **frozen 与 gain，B=4、T=32**；用 B=1、T=8 作为排错配置。换入真实选定子图和小型图像 encoder，仍用合成损失或固定录制画面验证计算，不直接开长时间训练。

检查至少：encoder 有有限且非零梯度、冻结边值不更新、gain 梯度可用、隐藏状态随时间变化、reset 恢复初始状态，以及 forward/backward/优化器和图像缓存的总显存。GPU 整卡占用应保留至少约 1.5 GiB 余量，目标训练进程增量预算不超过约 6 GiB；可用资源变化时按实测调整。

通过后再比较 T=16/32/64、B=1/4/8。**本次只实测到 T=32、B=4；T=64 和 B=8 尚未证明可行。** 第一版每次策略决策先执行一次网络更新；若每个游戏决策内部更新 K 次，必须将实际展开长度视为 K×T 并重新验收。

如果采用每 4 游戏帧一个决策，在约 60 fps 模拟时间下，T=32 覆盖约 2.1 秒。跨片段可保留隐藏状态数值，但截断梯度；保留数值不代表跨整个 episode 反传。这个初始窗口是否足够学会驾驶必须由任务结果判断。

### C. 学习试验矩阵

资源验收和任务判定通过之后，再实施带循环状态的 RL：

| 试验 | 配置建议 | 回答的问题 |
|---|---|---|
| 普通小型 CNN+GRU 基线 | 相同画面、动作、奖励、游戏步数预算 | 游戏任务与 RL 管线能否学会 |
| 固定连接组 | 约 8k 子图，B=4、T=32，训练 encoder/readout | 固定结构/动态是否支持任务 |
| 少量内部参数 | 同图同配置，加每神经元 gain；后续可另测类型共享 gain | 少量内部适应是否改善结果 |
| 全边权小规模对照 | 先约 2k、B=1、T=8；通过后最多扩到已验收的约 8k | 全边训练带来多少任务收益与成本 |

每个设置至少 3 个随机种子，使用相同 environment-step 预算，并记录实际训练 wall time。学习率、PPO rollout 长度与 epoch 数应在真实管线资源测量后确定，不能由本次平方损失 benchmark 推出。PPO rollout 长度可以长于训练片段 T，但要正确处理循环初始状态和片段边界。

先以稳定完成一圈作为阶段门槛，最终以五圈完赛率与成功完赛时间衡量。评估固定存档与轻微起始扰动；同时报告有效进度、逆行和撞墙次数。reward 数值上升不能单独视为学会驾驶。

### D. 扩规模与全脑决策

frozen/gain 在约 8k 上通过真实任务和资源检查后，才尝试约 32k；本次只有该规模的合成 B=1 测量，不能直接承诺真实批量图像训练开销。

全边权路线在扩大前，先验证一个没有 N² 稠密临时量的梯度实现/稀疏布局：与小型稠密参考核对输出与边梯度，检查内存随 E、B、T 的增长，再重复本测试矩阵。不能只换一个 API 名称就假定问题解决。

在这些条件满足前，不安排 16.5 万神经元的全边权 PPO，不承诺全脑训练显存或完成时间。当前结论是“小规模 frozen/gain 已有计算依据，全脑全边权原生 COO 路线不可直接采用”。

从 `flykart/` 运行：

```bash
uv venv --python 3.12 .venv-bench
uv pip install --python .venv-bench/bin/python --index-strategy unsafe-best-match -r requirements-bench.txt
.venv-bench/bin/python tests/bench_connectome.py
.venv-bench/bin/python tests/profile_sparse_backward.py
```

已存在环境不需要重新创建。完整测试会覆盖生成的结果 JSON，约产生 19 个隔离子进程，其中两个配置预计触发受控 OOM；不会写入 ROM 或 MaleCNS 原始文件。

- `tests/bench_connectome.py`：合成 benchmark。
- `tests/connectome_benchmark.json`：环境、每次测量、梯度范数、OOM 原文。
- `tests/profile_sparse_backward.py` 与 `tests/sparse_backward_profile.json`：稀疏梯度中间算子证据。
- `requirements-bench.txt`：独立环境主依赖版本。
