# 脑网络内部更新次数对照

本轮检验每个游戏动作之前进行更多神经状态更新是否能改善视觉学习，保持旧视觉接口，不叠加上轮可训练投影。候选为1/2/4次内部更新，1次复用既有监督基线。

## 结论

**多做内部更新打通了当前画面到当前动作的梯度通路，且2次更新小幅改善了动作预测，但没有解决稳定视觉驾驶。** 2次更新三个seed的测试平衡准确率平均39.8%（旧基线36.2%），冻结首帧为35.6%；正常视觉greedy通过9/51、固定首帧4/51、时间表11/51，未超过开环时间表。三个seed正常视觉分别6/17、3/17、0/17，仍不稳健。随机采样正常16/153、固定13/153、时间表31/153，也未显示优于时间表的任务收益。

| 配置 | 训练seed数 | 测试正常/固定平衡准确率 | greedy正常/固定/时间表 |
|---|---:|---:|---|
| 1次原基线 | 3 | 36.2% / 35.1% | 7/51、12/51、19/51 |
| 2次内部更新 | 3 | 39.8% / 35.6% | 9/51、4/51、11/51 |
| 4次内部更新 | 1 | 34.6% / 33.8% | 3/17、2/17、0/17 |

4次仅完成seed0试点，不能把它与3seed结果当作同等精度的比较。候选选择按预设验证门槛完成，未用测试成绩扩展；2次通过的是“值得复验”的门槛，不等于通过最终任务验收。测试集重复用于诊断，17个起点跨seed重复也不构成51个独立起点。

当前证据使“只是神经传播比游戏动作慢”不足以单独解释失败，也不证明传播速度完全无关。更长内部循环同时改变收缩、记忆和反传深度，不能简单以4次失败否定更合理的神经动力学。比较的是相同监督样本/更新预算，新增计算确实有成本。

## 建议的下一步（未执行）

不继续盲目增加到8/16次内部迭代。优先检查表示是否可解码：在同一示范与轨迹划分上，分别对CNN特征、视觉/中间节点和运动读出训练冻结表示的线性或小型非线性动作探针，同时报告常数/时间基线。这能帮助区分“任务信息未到达读出”与“已有信息但现有头或优化未利用”。探针成功本身仍需闭环验证。

若CNN特征可解码但运动读出不行，再针对读出位置、可训练稀疏适配或更合适的有记忆动力学做单变量改造；若两端都不行，则先固定已经能用视觉的GRU/CNN表示作诊断输入，检查固定图是否能保留其任务信息。也可把GRU+PPO作为另一独立研究线，但本轮未开始PPO训练。现有结果仍然支持首先处理图表示与可训练性，而非仅微调RL超参数。

## 实验设计

每次决策只编码一次当前画面，得到相同signal；随后对h执行k次原更新公式，再读取actor。episode起点清零只执行一次，不能在每个内部步重置隐藏状态。动作仍持续8个游戏帧，输入图像、固定W、gain、CNN/actor、奖励任务均不变；没有PPO或critic训练。

k=1与旧模型等价；k=2使至少一条连接可在当前决策内传播；k=4使视觉到读出最短路径1–3条边均可在当前决策内到达。这只说明结构通路变短，不保证信号幅度或任务信息足够。内部迭代反复使用同一幅画面，不额外获得游戏帧。

实现检查以随机帧测试k=1/2/4：与旧模型重复调用k次（仅第一次应用reset）逐项一致；训练chunk和在线Context也一致。在零初始隐藏状态下，当前帧到首个动作logit的梯度范数分别为0、1.51e-6、4.37e-6（只是一批随机输入的局部梯度，不是学习能力指标）。

训练复用43条轨迹、验证6条、诊断测试17条。每组256更新、batch8、BPTT32决策、历史64决策、同一Adam/类别加权交叉熵/随机批次顺序。因为一决策有k个神经步，BPTT实际展开32k神经更新，历史重建最多64k步。

先以seed0训练k=2和k=4，在任何测试评估之前，用验证集选择候选并应用预设复验门槛：正常平衡准确率至少比旧seed0最佳高5个百分点，并至少比冻结首帧高5个百分点。通过才追加所选候选seed1/2复验；不通过则不扩大预算。本轮协议在prepare阶段写入protocol.json，测试成绩不会用于扩展训练。

每个已训练模型都进行正常、固定首帧、纯时间表闭环；各含greedy及动作采样seed8100–8102，每组204局。保存全部动作与逐起点结果。测试起点是前轮已见的诊断集，并非新的独立测试；单seed试点不能当作跨seed稳健性结论。

更多内部更新还同时增强每个游戏决策的收缩并改变反传路径。若单神经步当前收缩界约0.9，则每游戏决策k=1/2/4约为0.9/0.81/0.656；这不是纯粹的延迟消融，也不能把任何成功/失败只归因于延迟。实际gain会训练，数值仅作尺度解释。

## 实现与复现

独立代码 `training/microsteps_experiment.py` 继承原GainPolicy，参数集合与初始tensor完全相同，复用已有监督训练器与评估器。旧model.py、旧输入接口和训练checkpoint不改。训练结束检查有效样本呈现次数与对应原基线一致、所有初始tensor完全相同、W不变；评估前后校验checkpoint hash。

在flykart目录执行（prepare要求输出目录不存在）：

```bash
.venv-bench/bin/python -m training.microsteps_experiment prepare
.venv-bench/bin/python -m training.microsteps_experiment run
.venv-bench/bin/python tests/summarize_microsteps.py
```

输出在 `runs/neural_microsteps_v1/`，k2/k4各自的plan记录内部更新次数；checkpoint中的config包含该plan的hash。加载模型必须按所属plan构造对应内部次数，不能把同形状参数误当作相同动力学。
